## 一、排查方法（先说明，因为结论的可信度全在这里）

1. **不靠肉眼猜，先造尺子。**
   - 精灵图问题：用 `/usr/bin/python3`（numpy + PIL + scipy）逐帧量 `alpha≥16` 的包围盒、脚底线、

     `run f0 短裤 31×38 / 腰→脚 68px` vs `jump f0 23×23 / 56px` → 判定「三张表画的不是同一个尺寸」。

**连带跳过了阶段 3 的两趟（滚浪机制、钥匙门流程）**——这才是"为什么布局改了但浪没改"的真正原因。
修法：全项目门禁从并行区里挪出来，改成**并行结束后的一个串行 Typecheck 阶段**。

### 4.2 方案书自己也有两个错（被"数学校验"agent 打对台打出来）

- 用"顶点触发二段跳 = 596.9px"证明"必须踩浪"，但 `Player` 的二段跳是**直接覆写速度**，
  "快落地前才补跳"严格更优（实测 679.2px）→ 结论反了（P0-3/P0-4）。

**教训：设计文档里的物理推导必须用真实代码路径复核，不能只做静力学估算。**

## 七、角色"左右移动跳帧 / 大小不一"收口（第三轮，主代理）

| # | 现象 | 根因 | 修法 | 验证 |
|---|---|---|---|---|
| C1 | 左右换向时**腿的姿势回跳**（读作跳帧） | 换向时 `vx` 要穿过 0，一旦被某一帧采到 `speedRatio ≤ 0.08` 就切回 idle；再回 run 时 `playAnim()` 先 `anims.stop()` 再 `play()` → **循环从第 0 帧重启** | 新增 `RUN_HOLD_MS = 140` 保持期：一旦跑起来，穿过 0 的窗口内不切动画 | 确定性探针逐帧取帧号：右跑 → 立刻反向 → 再反向，帧号 12,13,15,0↯,2,3,5,6 → 7..13 → 14,0↯,1,3,4,6（只有循环自然回绕到 0，**换向处没有重启**） |
| C2 | 换向时**朝向偶尔卡住**（角色朝反方向跑） | `squash()` 的 tween 目标是"当时的 facing"，换向时 `update()` 直接改 `view.scaleX`，被 tween 每帧写回旧值；tween 结束后 `displayedFacing` 已更新、不会再赋值 | 抽出 `retargetSquashTween()`，换向时若压扁动画在跑就重定目标 | 同上探针：`scaleX` 与 `facing` 全程一致 |
| C3 | 角色**时大时小**（残留缩放） | 压扁/拉伸写在 `view.scaleX/scaleY` 上，压扁 tween 被 kill（抓鸥/冻结/重生）时 `squashing` 标志永远停在 true → 缩放再也不会回 1 | 用 `tweens.isTweening(view)` 当唯一真相让标志自愈 + 地面上把 `scaleY` 收敛到 1、`scaleX` 校正回 `facing` | 探针全程 `sx=1, sy=1` |
| — | （尺寸那一半已在上表 F2/F3 修掉：三张表 1.29 倍尺度差 + 脚底线差 + 无待机动画） | | | |

### 方法论教训（值得写进规范）

**手动步进（`game.loop.sleep()` + `game.step()`）不会推进 tween**（探针里 tween `progress` 恒 0、`isPlaying()` 恒 true）。
用它测动画状态机是可以的（AnimManager 会走），但**不能用它判断缩放/tween 残留**——我第一版就因此误判出一个"缩放永久卡住"的假 bug。
另外探针取状态前要**先清存档**：存档里带 `forestKeyCollected=true` 时，角色跑进石门会直接触发通关 `freeze()`，
位置不动、速度恒 0，而此时 Phaser 仍在播动画，很容易读成"跑动连续性正常"。

## 八、B 方案：让"必须踩浪"成立（第四轮，主代理）

**目标**：让两朵限时滚浪成为必经环节（原先可以被一次二段跳绕过）。

### 关键阈值（用 `tools/sim-jumps.mjs` 算的，之前的 596.9px 口径是错的）

| 落差 | 单跳满蓄力 | 二段跳最晚触发（真正的上限） |
|---|---|---|
| 起跳高台→海心礁（+110） | 344px | **665px** |
| 冲刺礁→右岸（+35） | 323px | **648px** |

### 改动（4 个数字 + 1 处复活点）

| 改动 | 前 → 后 | 为什么 |
|---|---|---|
| 删掉"浪后落脚礁"（role `wave-landing`，2370） | 有 → 无 | 它的缝只有 459px，二段跳随便过；右移它又会撞石门 |
| `landing.left` | 2500 → **2600** | 缝 = 2600 − 1875.32 = **711px > 666px**（含身体半径），二段跳够不到 |
| `waves[1].ridgeCenter` | 2200 → **2240** | 浪体只有 78px 宽，按住右走 0.3s 就走出浪面；而站在浪上起跳时水平速度≈0，最后一跳比"满速模型"短。右移 40px 后**站着满蓄力起跳**也能落到右岸 |
| 复活点表 | 去掉右岸那一档 | 右岸左缘 30px 外就是门区（2599.8~2760.2），在右岸复活会一睁眼压在门区里（有钥匙=直接进门 / 没钥匙=反复刷"先去摘钥匙"）；现在最后的安全点是冲刺礁，死在浪区就重跑这一段（正好是这一段的代价） |

### 验证

- **单测**（新增第 4 条策略断言）：`浪区强制力：冲刺礁起跳点 x=1889 · 右岸左缘 2600 · 距离 711px > 二段跳射程 666px`；同时断言两朵浪**必须**踩得到（否则就不是"必经"而是"不可能"）。
- **真游戏探针**（确定性步进，清存档）：骑 W2 到 `rolled=70.7` 时角色在 x=2311、`onFloor=true`（被浪托着走）；随后满蓄力起跳 → **落点 2630**；先助跑 8 帧再起跳 → **落点 2661**；而只按 1 帧的轻点会差 60px 落水（这正是想要的张力，二段跳是兜底）。
- **E2E 14/14 通过、0 console error**；`tsc` 干净；单测 17/17。

### 副作用（都已处理）
