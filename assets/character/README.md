# 年年角色动画资产

这组资产是年年 Smart Version 的第一套游戏内横向动画条，按 Recall Game Demo 的单行 sprite sheet 结构制作。人物保持双麻花辫、砖红色发结、雀斑和晒红的脸颊，穿暖白短袖、低饱和蓝绿色短裤并赤脚。

## 文件

| 文件 | 动作 | 帧数 | 单帧尺寸 | 整图尺寸 |
| --- | --- | ---: | ---: | ---: |
| `char-niannian-run-right-128x160-16f.png` | 向右跑 | 16 | 128 × 160 | 2048 × 160 |
| `char-niannian-jump-right-128x160-16f.png` | 向右起跳、腾空、准备落地 | 16 | 128 × 160 | 2048 × 160 |
| `char-niannian-grab-up-right-128x160-16f.png` | 起跳并向上抓住物体、悬挂稳定 | 16 | 128 × 160 | 2048 × 160 |

三张图均为 RGBA 透明背景，帧序从左到右排列。图中没有画出可抓取物；钥匙、海鸥或其他交互物应由游戏单独渲染。向左动作可在运行时水平翻转，不需要再存一套图片。

## Phaser 接入参考

```ts
this.load.spritesheet('niannian-run', runUrl, {
  frameWidth: 128,
  frameHeight: 160,
});
```

建议初始显示缩放为 `0.525`，对应约 `67 × 84` 的画面尺寸，和 Recall Game Demo 中鱼鱼的显示高度接近。Seek 现在的碰撞体是 `36 × 72`（窄于可见身体、矮约 4px，属横版常规宽容）。三组动画在 Seek 里的实际接入参数：

- 跑步：`frameRate: 26`，循环播放（16 帧 @26fps ≈ 0.535s，回到旧 meimei 的摆腿节奏；按 16fps 走一圈 1s，实机读作“脚下打滑”）。
- 跳跃：按垂直速度取帧（4-11），不整段播放；下落/从边缘走落走 9-11。
- 向上抓取：从第 **4** 帧起播到第 10 帧（0-3 是地面蹲地预备，空中抓住时播会看到“空中蹲一下再伸手”），抓住后循环 11-15（8fps）。
- 待机：借用跳图第 0 帧（静立姿），叠加程序呼吸（见下）。

## 生成方向

以年年 Smart Version 为人物基准：古灵精怪、顽皮、有创造力，动作轻快但重心清晰。画面使用暖棕色手绘线条、柔和哑光水彩/水粉肌理、低饱和蓝绿色与暖白色，保持角色设定图的笔触和颜色。跑步强调双辫与衣摆的跟随；跳跃包含预备、蹬地、腾空和落地前姿态；抓取包含预备、起跳、双手上伸、抓住和稳定悬挂。

## 洋红抠图残留（2026-10-02 处理）

生图用洋红底（`#ff00ff`）抠图的副产物：三张序列帧的角色轮廓上原本带一圈洋红像素
（半透明光晕为主、局部实心），游戏里读作「角色身上套着一圈紫光」，在海面/礁石的冷色背景上尤其明显。

已用 `tools/despill.py` 就地清理（原图在 git 历史 `6a47ac1`，可随时取回）：

```bash
/usr/bin/python3 tools/despill.py assets/character/char-niannian-run-right-128x160-16f.png
/usr/bin/python3 tools/despill.py assets/character --report   # 体检，只统计不写文件
```

- 清理量：run 22 842 / jump 12 906 / grab 13 001 个溢出像素，处理后三张图溢出像素均为 **0**。
- 做法：溢出像素（`min(r,b) - g > 20`）改用最近的非溢出像素颜色补色；轮廓上的溢出按强度收 alpha，
  **轮廓内部**的溢出只补色不动 alpha（避免把辫子等实心部位打穿）。
- **美术侧仍建议重新导出**：本地清理能救回轮廓，但原本该保留的墨线描边会随光晕一起被削淡。
  生图时请用纯洋红底且不要让角色带洋红光晕/描边。

## 绘制尺度与脚底线（2026-10 实测，已接入游戏）

三张图**不是同一绘制尺度**上生成的。用刚性部位做尺度代理（短裤色块 run 34×31 对 jump 27×23、脸（皮肤）宽 30 对 23、腰→脚底 68 对 56）得到 run 约为 jump/grab 的 **1.26-1.30 倍**；把 run f0 与 jump f0 的脚底对齐做 1.0 / 1.19 / 1.29 三档同屏 A/B，也是 1.29 档头部与躯干才对得齐，1.19 档待机明显偏小。

游戏侧按下面这张表补偿（常量在 `src/gameplay/Player.ts` 顶部）：

| 序列 | 显示缩放 | 脚底参考线（源图 y） |
| --- | ---: | ---: |
| run | 0.525 | 153 |
| jump（空中帧） | 0.68 | 153 |
| jump f0（待机帧） | 0.68 | **146** |
| grab | 0.68 | 不用脚底，用握点（拳心 (75, 11)） |

逐帧脚底线实测（alpha≥128 的最低像素在帧内的源 y）：

- run：`153, 151, 153, 150, 140, 153, 153, 152, 152, 151, 133, 141, 151, 152, 152, 152`
- jump：`146, 146, 146, 146, 131, 125, 129, 109, 111, 124, 135, 146, 152, 153, 153, 153`
- grab：`153, 152, 152, 152, 145, 141, 144, 142, 132, 131, 131, 142, 133, 141, 145, 150`

读法：

- run 的头顶恒在 y=9、只有腿在动（美术是按“身体不动、腿动”画的），f4/f10/f11 是双脚离地的帧，所以跑动只用**一条**脚底线；逐帧对齐会把身体顶得上下抽动。
- jump f0 的脚底在 146，比同图触地帧（153）高 7 源 px：待机必须按 146 单独对齐，否则一共用锚点就悬空 4.8px，跑步停下来时“脚一抬、人一跳”。
- grab 的握点在拳心 (75, 11)（拳头占源 y=7..16，y=17 起是 8px 宽的前臂），不取指尖：取 6.5 会把海鸥双脚画到拳头顶端，读作“用指尖顶着”。

**美术侧重新导出后必须重测这几张表**（重跑一次逐帧量测），否则会回到“脚底悬空 / 切换时缩一跳”。

## 待机动画（现为程序呼吸）

三张图里可用的“站立”帧只有跳图 f0 与 f15，二者按脚底对齐后头差 19 源 px，读作下蹲而不是呼吸；因此没有可用的 idle 帧对。游戏里待机＝跳图 f0 + 程序呼吸（纵向缩放 ±1.5%、周期 1.9s，脚底钉在碰撞体底边，只有头顶起伏约 ±1.2px）。

真正的 idle 行建议按下面的规格补：`char-niannian-idle-right-128x160-6f.png`（**新增文件名，不动既有三张**），6 帧单排、站姿、头顶位移 ≤2 源 px、含 1 次眨眼，接入建议 6fps。

## 导入检查

- 切图参数固定为 `128 × 160`，不要自动裁边。
- 每行只有一排，共 16 帧；读取索引为 `0–15`。
- 角色朝向为右；水平翻转时保持碰撞体中心不变。
- 以脚底或身体中心作为统一锚点，避免动画切换时位置跳动。
- **三张图必须同一绘制尺度**：现 run 是 jump/grab 的 1.29 倍，游戏靠分表缩放补偿，但补偿会把跑步↔待机瞬间的尺寸差暴露出来。
- **脚底线必须落在同一源 y**（建议 153）：现 jump f0 在 146、同图触地帧在 153，待机要单独对齐。
- 空中只取 4-11（0-3 是地面蹲地预备、12 之后是触地恢复）；如果要画跟着身体弹跳的空中帧，请把这一套单独存一张，不要混进跳跃序列。
- 修正一条既有描述：跳图 **f0 的脚底是源 y=146**（不是 153）。
