## 当前程序接口

- 逻辑世界是 1900×540，摄像机视口约 960×540，横向跟随角色。
- `ForestScene.preload()` 加载场景图片；`create()` 在背景深度绘制图片，并用 `placeParallax()` 设置视差和垂直落点。
- `Terrain` 创建独立的不可见碰撞矩形，再在相同坐标绘制可见地面/平台。背景图片本身不参与碰撞。
- 当前工作区里的跳跃段坐标：地面 `(x=0, y=500, w=700)`；平台 `(740,430,110)`、`(900,360,110)`、`(1060,430,100)`；后段地面 `(1180,500,w=720)`。浮台碰撞高度为 24。这里描述的是当前工作区代码，不是 Git 基线自带的正式美术规范。

## 素材分层顺序

1. **远景**：天空、少量云、不同轮廓的岛屿，视差最慢（建议先试 0.05–0.10）。
2. **海面**：几条宽阔的蓝绿色水色带，视差略快（建议 0.12–0.20）。
3. **中景**：左侧少量海边房屋、岸线和树，视差约 0.3–0.5。
4. **可玩地形**：沙滩与逐级升高、再下降的岩台，跟随世界坐标全速滚动；顶面要对齐碰撞 y 值。
5. **近景**：透明的两侧植物、少量岩石，视差接近 1，放在角色后方或仅在画面边缘遮挡；不得遮住跳台和角色主体。

视差层必须用 `placeParallax()` 做初始位置反算，不能直接把屏幕坐标当世界坐标，否则背景可能因摄像机垂直居中而错位。最终倍率以实机画面调校为准。

## 连续沙岸与跳跃路线

新概念图把海岸画成连续阶梯，当前物理碰撞却是三块 24px 高的浮台和两段平地，中间有 20–50px 缺口。不能直接把概念全景当成最终可玩地形，否则画出的连续沙面会让玩家误以为缺口可走。

**建议路线：**把碰撞轮廓也改成连续的阶梯海岸，保留低滩 → 约 70px 上跳 → 再上跳到最高台 → 下跳 → 回到长沙滩的节奏。每一级的顶面与地形碰撞顶面对齐，阶梯立面连续相接。这样画面中的沙岸连续，同时竖直高差仍要求玩家跳跃。不要用一张背景图模拟可踩地形。

如果设计上必须保留当前碰撞坐标，则应画出平台之间真实的低洼/海水缺口，不能把视觉沙路画成连续平地。

实现前需确认阶梯块的具体 x 范围，再按 `Terrain` 能支持的碰撞形状拆成矩形或扩展为折线/多边形碰撞；概念图本身不提供精确坐标。

不论选择哪种，背景/前景只负责画面，落脚判断仍由碰撞体负责。概念图目前为 2170×725（约 3:1），与游戏世界 1900×540 不同，需在拆层后按实际坐标摆放，不能原比例整张覆盖到 1900×540。
