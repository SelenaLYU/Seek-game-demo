## Decision: 滚浪承载角色时锁定浪面高度

## Context

测试第一关时观察到角色踩在滚浪上会出现跳帧/像浮空。原实现的 `updateWaves()` 在 `rolling` 状态仍按正弦曲线让浪面上下浮动，而 `checkWaveRide()` 只按 `carryX` 横向移动角色。角色动画状态则由 `Player.update()` 的 Arcade `onFloor()` 判定决定；承重判定另有 18px 的上下窗口，可能继续把已离开浪面的角色当成骑浪。

旧 E2E 只检查滚浪 500ms 内是否横移，未采样人物着地状态和纵向位移，因此即使这类抖动存在也会通过。

隔离复现与修复后的 500ms 实测（同一 E2E 场景，31 个采样点）：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 离地采样 / 跳跃或下落状态 | 18/31 | 0/31 |
| 浪面纵向变化 | 9.16px | 0px |
| 人物纵向变化 | 9.62px | 0.85px |
| 最大脚底—浪面间距 | 0.89px | 0px |

## Decision

浪待机时保留上下浮动；玩家踩中浪并进入 `rolling` 时，将当时的浪面高度保存为 `rollY`，滚动期间只横向前移，不再上下浮动。承重判定窗口从 18px 收紧至 8px，只容忍物理碰撞的一帧误差。

## Alternatives considered

- **滚动时继续上下浮动并同时垂直搬运角色**：需要同步 Arcade Body、Game Object 与落地动画，容易出现重复搬运或碰撞状态错位。
- **所有状态都取消浪面浮动**：实现简单，但会失去待机浪的视觉动感；不如仅在承载角色时锁高。
- **只缩小承重窗口**：不能消除浪体与玩家一起上下跳动，也可能让承重判定丢失，未解决根因。

## Trade-offs accepted

浪在滚动承载玩家期间暂时不做垂直起伏，但保持水平滚动和贴图动势；离开承载状态并复位后，待机起伏恢复。若之后需要滚动态的竖向波形，应改为经过物理验证的整体搬运，而不是直接恢复正弦位移。

## Follow-up: 终点与实玩复核

- 取消拾钥匙后“先走出门洞再走回”的额外门槛。仍保留解锁延迟与落地条件；钥匙状态提示改为“落地后就能从门口进入”。E2E 单独验证：延迟未到时不进门；延迟已到但仍在空中时仍不进门；自然落地后从门口进入。
- 海鸥抓牢时增加短暂操作提示“按空格甩出，飞向海心落脚礁”，并由 E2E 校验。Codely-VL 对比抓取过渡帧与稳定悬挂帧后，确认先前的“抓握有间隙”主要是过渡帧误读；稳定挂住的截图手部与海鸥脚爪接触成立。
- 在独立浏览器中通过游戏触控输入连续实际走完整条路线，**游玩过程中未调用 `teleportTo`**：出生礁 → 620 → 830 → 1040 → 海鸥抓取/松手 → 海心礁 → 浪前爬升礁 → 冲刺礁 → 骑浪 → 浪后礁 → 岸边 → 取钥匙 → 落地进门。结果：生命保持 3，最终 `room` 场景 active。
- 对比“骑浪时脚下椭圆泡沫斑”前后截图后，Codely-VL 判定稳定画面本身已由白沫形成接触，平滑椭圆反而像 UI；该视觉试验已撤回，未保留椭圆或修改 PNG。
- 礁石可读性：`addReef()` 只按 `reefStandBoxes()` 在真实碰撞站面添加不规则亮苔色斑，底图装饰礁不改、原始 PNG 不改；E2E 截图 `screenshots/test-niannian-idle-verified.png` 可查看。它是视觉提示，不更改碰撞数据；玩家主观可读性仍可在主分支实机反馈后微调。
