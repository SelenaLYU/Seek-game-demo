# 硬约束：记忆之岛 3D 场景不允许出现穿模

日期：2026-10-05
状态：生效中（用户明确要求）。**每个会话开工前先读这条。**
执行机制：`src/island/clipping.ts` + `tests/islandClipping.test.mjs`（纯函数判定 + 回归测试）

## Context

用户 2026-10-05 看截图时的原话：「一定记住，这个 3d 场景里面不能有穿模的情况」。

这不是一句观感偏好，而是这个场景最容易反复出现的一类缺陷：岛上除了六栋 Tripo 建筑和主角，
其余（地形、崖壁、溪流、道路、木桥、栈桥、树木）都是程序化生成的。程序化生成意味着
「位置由算式决定」，只要算式里少了某一项约束，就会稳定地穿模，而且**在总览视角下不容易被发现**。

已经发生过的实例（都是这一条约束的下属问题）：

| 现场 | 成因 | 位置 |
| --- | --- | --- |
| 左侧木栈桥桥面在半空断掉、桥柱插进岛体裙边 | 桥面是固定尺寸的板，按地形高度定位，没有和岸线做衔接 | `MemoryIsland.ts` 的 `dock`（`dockDeck` / pier posts） |
| 贝壳屋底部的石头/灌木陷进沙地 | 建筑模型自带装饰，落位按「footprint 里地形最高点」摆，坡地遮挡 | 建筑落位里的 `baseGround = max(地形采样)` |
| 一棵树压在贝壳屋前角 | 程序化树位置没有把建筑 footprint 当禁区 | 岛上植被散布 |
| 岛缘可见「塑料底座墙」（崖壁分段换色 + 直筒裙边） | 崖壁是按角度分段的直筒网格，没有凹凸 | `cliff`/skirt 几何 |
| 树/道具探出岛缘悬在水上 | 散布点只判了「在陆地上」，没判「离岸距离」 | 散布点采样 |

## Decision

**「不许穿模」按下面四条判定执行，全部写进代码，不靠人眼验收：**

1. `floating` —— 物体最低点高于地形 > `MAX_FLOAT`（0.02 世界单位）；
2. `sunken` —— 低于地形 > `MAX_SINK`（0.08。坡地上刻意留的重叠不算穿模，超过就是「只剩半截」）；
3. `overlap` —— 两件物体的**占地圆**相交（用占地圆，不用包围球：树冠之间允许交错，树干与底座不允许）；
4. `building` / `keep-clear` —— 占地圆压到建筑占地盒，或压到必须留空的圆（门前触发圈、广场、桥头）。

摆放与复核共用同一套判定：散布时每个候选点先过 `canPlace`（不过就丢弃），
摆完后再跑 `auditPlacements` 做全量复核并在 dev 下打日志。
**禁止**在散布代码里另写一套「差不多」的碰撞判断——历史上这类失效都是这么来的。

散布必须可复现：用 `seededRandom(seed)`，同一个种子每次得到同一张岛，
这样「昨天验收过、今天又穿模」才可能复现和回归。

## Alternatives considered

- **只在截图里人眼找穿模**：总览视角下几十像素的物件互相压叠根本看不出来，
  而且每次美术改动都要重看一遍，等于没有约束。
- **上物理引擎做真碰撞检测**：对这个场景过重（上千件静态装饰），而且需要 GPU/浏览器才能跑，
  无法进 `npm test`。占地圆 + 轴的几何判定足够覆盖实际出现过的四类问题。
- **完全不做散布，避免风险**：等于放弃用户要的「岩石/植被/珊瑚散布」，且不解决已有穿模。

## Trade-offs accepted

- 占地圆是**保守近似**：允许树冠在视觉上交叠（近场会看到一点穿插），换取判定简单、可测、可复现。
  如果以后发现树冠穿插同样刺眼，就把 `radius` 换成椭圆或加一条「树冠高度带」判定。
- `MAX_SINK = 0.08` 是经验值：更小会在地形起伏处露出缝（悬浮感），更大就会重新出现「陷进去一半」。
- 判定是 2D（x/z）的，不做高度分层。空中不可达的物件（例如屋顶装饰）不能这么判。
